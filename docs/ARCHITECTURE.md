# 구조와 역공학 메모

## 런타임 구성

```text
Dead Space.exe
  └─ xinput1_3.dll                 DeadSpace2008Fixes 기반 메인 프록시
       ├─ 실제 System32 XInput 전달
       ├─ MinHook 기반 수정 기능
       ├─ SDL3 컨트롤러 계층
       └─ LoadLibrary(ds1k_utf8.dll)
            └─ 두 게임 문자열 루프의 UTF-8 처리 훅
```

두 DLL을 각각 XInput 프록시로 설치하지 않는다. 메인 `xinput1_3.dll`이 사이드카
`ds1k_utf8.dll`을 명시적으로 불러온다.

## UTF-8 훅

`src/dllmain.cpp`는 실행 이미지에서 Steam/EA App 1.0.0.222 문자열 처리 루프 두 곳을
고정 RVA가 아닌 바이트 시그니처로 찾는다. 후보를 찾은 뒤 주변 분기, 스택 오프셋, 글리프
조회와 포인터 증가 명령까지 예상 바이트와 비교한다. 하나라도 다르면 어떠한 코드도
기록하지 않는다.

훅은 1·2·3바이트 UTF-8 시퀀스를 BMP 코드포인트로 디코딩하고, 기존 1바이트 증가를
실제 UTF-8 길이 증가로 바꾼다. FFN 조회에는 16비트 코드포인트를 전달한다. 4바이트
UTF-8/비BMP 문자는 현재 지원하지 않는다.

성공 여부는 다음 로그로 확인한다.

```text
DS1K/DS1K.log
UTF-8 hooks installed. f1=... f2=...
```

다른 EXE 버전을 지원할 때는 단순히 검증을 제거하지 말고, 별도의 시그니처와 전체 예상
바이트 세트를 추가해야 한다.

두 에디션의 디스크 EXE는 보호된 `.text`를 사용해 정적 파일에서 시그니처가 보이지
않는다. 실행 중 복호화된 이미지에서는 같은 시그니처가 확인된다. 관찰한 함수 주소는
Steam `0x00740901`/`0x007431E4`, EA App `0x007408D1`/`0x007431B4`이며 두 함수가
동일하게 `0x30` 이동한다. 고정 주소를 사용하지 않으므로 별도 EA 전용 훅은 필요 없다.

## 번역 리소스

게임 문자열은 32비트 ID와 LCH2 레코드로 관리한다. CSV의 `id`가 기본 키이고
`english`는 검토용, `translation`은 실제 출력 문자열이다. 생성기는 원본 레코드
순서와 제외 항목의 원본 바이트를 보존하면서 CSV에 있는 4,550개 항목만 교체한다.

제외 기준은 다음과 같다.

- 유효하지 않은 UTF-8 원문
- 의미를 판단하기 어려운 한 글자 문자열
- `[]`처럼 문자와 숫자가 전혀 없는 값

Steam 순정판에는 패치 출력 경로인 `D8CBB618.str`가 없고, EA App 영어판에는 같은
이름의 원본 파일이 이미 있다. 설치기는 Steam판에서는 부재 상태를 기록하고 EA
App판에서는 기존 파일을 백업한다. VPatch는 두 에디션의 원본 쌍을 동일한 한국어
결과물로 변환한다. 완성 글로벌 STR의 로캘 참조 테이블은 EA App판 구조와 일치한다.

## 글꼴 리소스

세 UI 글꼴은 같은 나눔바른고딕 Regular 패밀리로 완전히 다시 그린다.

- 아틀라스: 2048×1024, DXT5, 10 mip levels
- 논리 셀 상한: 32×32
- 글꼴 크기: 25px em
- 레코드 크기/오프셋: 공통 기준선에 배치한 실제 글리프 외곽으로 계산
- 글리프 간 투명 여백: 좌우 각 5px
- advance: 나눔바른고딕의 실제 측정값

Steam 원본 FFN은 필요한 기존 문자 목록을 결정하는 데만 사용한다. 픽셀과 metric은
재사용하지 않는다. CSV에서 발견한 비ASCII 문자와 원본 문자 목록을 합쳐 세 아틀라스에
동일하게 생성한다. 따라서 한 문장 안의 영문과 한글이 서로 다른 폰트 기준선·크기를
사용하지 않는다.

FFN에는 모든 글자를 32×32로 강제하지 않는다. 실제 외곽 폭·높이와 좌우 bearing을
기록하므로 `i`, `l`, 마침표, 괄호 같은 좁은 글자도 advance와 보이는 픽셀 위치가
일치한다. 32×32는 글리프가 같은 em/라인 박스 안에 들어오는지 확인하는 상한이다.

확장 FFN 작업본은 새 글리프를 넣을 충분한 레코드 수를 제공하는 컨테이너 역할만 한다.
저장소에는 해당 제3자 리소스를 포함하지 않는다.

## DeadSpace2008Fixes 통합 변경

upstream revision `ec7ae5cdb799af5494e483cb3357b897d8fe9fe1`을 기준으로 다음
DS1K 전용 변경을 포함한다.

- `dllmain.cpp`: 모듈 적용 표와 UTF-8 사이드카 로딩
- `SubtitleScale.cpp`: 데스크톱 해상도 대신 실제 게임 클라이언트 크기 사용, 720p
  이하 1.0배 하한
- `BorderlessWindow.cpp`: 포커스 복귀·이동·크기 변경 시 클라이언트 영역 커서 고정,
  포커스 이탈 시 해제, 게임 활성 상태에서 시스템 커서 숨김
- `Telemetry.cpp`: 프로세스 전체 WSAStartup을 막지 않고 `Dead Space.exe`에서 직접
  호출한 경우만 차단하여 Steam/SDL 스레드 충돌 방지
- `VersionString.cpp`: `Dead Space KR 0.1`과 `번역 검수용 버전` 표시

그 밖의 VSync, 타이머, 이방성 필터링, CPU affinity, DirectInput, 세이브 문자열,
로딩 화면, 컨트롤러 수정은 upstream 구조를 유지한다.

## 안전 원칙

- 패턴 검색 결과가 0이면 적용하지 않는다.
- 코드 기록 전 예상 원본 바이트를 검증한다.
- 백그라운드 창에는 `ClipCursor`를 적용하지 않는다.
- 게임 EXE 자체를 디스크에서 수정하지 않는다.
- 게임·Steam·SDL이 함께 사용하는 시스템 API 훅은 호출자 모듈을 구분한다.
