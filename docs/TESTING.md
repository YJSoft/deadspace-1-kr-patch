# 회귀 테스트 체크리스트

## 기본 실행

- [ ] Steam판 1.0.0.222 원본 EXE에서 실행된다.
- [ ] EA App판 1.0.0.222 원본 EXE에서 실행된다.
- [ ] `DS1K/DS1K.log`에 두 UTF-8 훅 설치 성공이 기록된다.
- [ ] 메인 화면에 `Dead Space KR 0.2`와 `번역 검수용 버전`이 두 줄로 표시된다.
- [ ] 새 게임 Easy 난이도로 시작해 첫 조작 가능 구간까지 진행된다.
- [ ] 저장과 불러오기가 동작한다.

## 설치 마법사

- [ ] Steam 등록 정보가 있으면 설치 폴더를 올바르게 제안한다.
- [ ] EA App 등록 정보가 있으면 설치 폴더를 올바르게 제안한다.
- [ ] 잘못된 폴더에서는 다음 단계로 진행되지 않는다.
- [ ] 현재 Steam 순정 설치본의 `12F4D5F8.str` 구조에서 최초 설치된다.
- [ ] 위 설치를 제거하면 `12F4D5F8.str`는 원본 해시로 유지되고 패치가 만든
      `D8CBB618.str`는 제거된다.
- [ ] EA App 순정 설치본의 기존 `D8CBB618.str`에서 최초 설치된다.
- [ ] EA App판 제거 후 기존 `D8CBB618.str`가 설치 전 해시로 복원된다.
- [ ] 깨끗한 원본 STR에서 한국어 STR 두 개를 생성하고 최초 원본을
      `DS1K_Backup`에 보존한다.
- [ ] 기존 `DS1K_Backup_v0.1`을 발견하면 내용을 복사하지 않고 `DS1K_Backup`으로
      폴더 이름만 변경한 뒤 업그레이드한다.
- [ ] 같은 설치본을 다시 실행해도 최초 백업을 덮어쓰지 않고 정상 재설치된다.
- [ ] 기존 설치를 발견하면 백업 원본으로 먼저 복원한 뒤 새 패치를 적용한다.
- [ ] 업그레이드 후 `DeadSpaceFixes.ini`의 사용자 설정이 유지된다.
- [ ] 설치한 커밋이 `DS1K_Patch/installed-version.txt`와 제거 레지스트리의
      `BuildCommit`에 기록된다.
- [ ] 백업 하나를 제거하거나 손상시키면 STR·DLL·설정을 바꾸지 않고 업그레이드가
      중단되며 게임 클라이언트의 원본 복구 안내가 표시된다.
- [ ] 위 상태에서 원본 STR를 복원해 다시 실행하면 백업을 재구성하고 설치된다.
- [ ] 수정되거나 지원하지 않는 STR에서는 게임 파일을 바꾸지 않고 설치가 중단된다.
- [ ] Windows 설치된 앱 또는 `DS1K_Patch/Uninstall.exe`에서 제거할 수 있다.
- [ ] 제거 후 원본 STR 해시가 설치 전과 일치하고 원래 없던 런타임 파일은 제거된다.
- [ ] 제거 후에도 안전 백업 폴더가 남는다.

## Linux / Steam Deck AppImage

- [ ] x86_64 AppImage가 Ubuntu 26.04에서 실행 권한 부여 후 바로 열린다.
- [ ] 일반 Steam과 Flatpak Steam 라이브러리 위치를 중복 없이 자동 탐색한다.
- [ ] 자동 탐색 실패 시 `Dead Space.exe`가 있는 폴더를 수동 선택할 수 있다.
- [ ] GUI에 `WINEDLLOVERRIDES="xinput1_3=n,b" %command%`가 정확히 표시되고
      `옵션 복사` 버튼으로 클립보드에 복사된다.
- [ ] Steam 원본의 최소 테스트 복사본에서 설치 결과와 매니페스트의 두 출력
      SHA-256이 일치한다.
- [ ] AppImage로 재설치할 때 버전 없는 백업 마이그레이션과 사용자 INI 보존이
      동작한다.
- [ ] 백업이 손실된 패치 상태에서는 현재 STR를 바꾸지 않고 설치가 중단된다.
- [ ] 제거 후 Steam 원본 두 입력의 SHA-256이 설치 전과 같고 원래 없던
      `D8CBB618.str`와 런타임 DLL이 제거된다.
- [ ] Steam 실행 옵션을 적용한 Proton 실행에서 `DS1K/DS1K.log`에 UTF-8 훅 성공이
      기록되고 한글이 mojibake 없이 표시된다.

## 번역과 글꼴

- [ ] 메인 메뉴의 한글·영문 공백이 유지된다.
- [ ] 제작진 화면에서 영문과 한글의 크기와 기준선이 일치한다.
- [ ] 임무 브리핑의 영문·숫자·한글이 같은 서체로 표시된다.
- [ ] `아이작, 나야`로 시작하는 니콜 로그 자막이 정상 표시된다.
- [ ] 긴 한 줄과 두 줄 자막에서 하단 잘림과 인접 글리프 artifact가 없다.
- [ ] 문서/오디오/영상 로그의 번역이 문자열 ID에 맞게 나온다.
- [ ] 네모·대체 문자·깨진 UTF-8이 없다.

## 해상도와 창

- [ ] 1280×720에서 자막이 원본보다 작아지지 않는다.
- [ ] 1920×1080과 2560×1440에서 자막이 자동 확대된다.
- [ ] 16:9 이외 화면비에서 자막 영역이 화면 밖으로 나가지 않는다.
- [ ] 보더리스 상태에서 Alt+Tab 이탈 시 커서 고정이 풀린다.
- [ ] 복귀 시 시스템 커서가 숨겨지고 마우스가 게임 클라이언트 밖으로 나가지 않는다.
- [ ] 멀티 모니터에서 화면 가장자리 클릭이 다른 창으로 포커스를 넘기지 않는다.

## 수정 기능

- [ ] `RemoveTelemetry=1`에서 Steam/SDL 스레드 예외가 발생하지 않는다.
- [ ] `BorderlessWindowed=0`에서 원래 창/전체 화면 동작으로 돌아온다.
- [ ] `FixSubtitleScale=0`에서 원작 자막 크기로 돌아온다.
- [ ] `SafeFPSCap=1`과 `0` 양쪽에서 새 게임이 시작된다.
- [ ] `SkipLoreVideos=1`에서 새로 재생한 문서·영상 로그를 F로 건너뛸 수 있다.
- [ ] PS/Xbox/Switch 계열 입력 장치가 있는 경우 1분 이상 유휴 상태 뒤에도 버튼과
      진동이 동작하고, 분리·재연결 후 다시 인식된다.

## 실패 안전성

- [ ] 지원하지 않는 EXE에서 예상 바이트 검증 실패 로그를 남기고 UTF-8 코드를 쓰지
      않는다.
- [ ] `ds1k_utf8.dll`이 없어도 메인 프록시가 명확한 로그를 남기며 다른 수정 기능을
      손상시키지 않는다.
- [ ] `SDL3.dll` 누락 시 원인을 진단할 수 있다.
